# LanScope · 局域网设备管家

对局域网进行自动化探测与设备管理的本地工具：全网段扫描、设备指纹、端口与服务识别、定时巡检、新设备与 ARP 欺骗告警、陌生设备深度侦察与风险评估，配一个浏览器里打开的深色控制台。

## 功能

- **主机发现**：scapy ARP 全网段扫描＋ping 扫描互补合并——实测两类方式各有对方发现不了的设备（手机省电模式可能漏 ARP，个别设备不回 ping）；无 Npcap 权限时自动降级为 ping＋ARP 表模式。
- **设备指纹**：反向 DNS／mDNS／NetBIOS／SSDP 四路解析主机名；MAC OUI 厂商库（内置精简库兜底，IEEE 全量库自动下载、每 30 天自动刷新）；按厂商＋端口＋服务特征推断设备类型（路由器／手机／电脑／电视／打印机／摄像头／IoT 等）。
- **端口与服务**：在线设备常见端口 connect 扫描（无需管理员权限），抓取 HTTP 标题与 SSH/FTP banner。
- **深度侦察**：对单台陌生设备做全端口扫描（1～65535，自动跳过本机被劫持端口）＋全部开放端口服务指纹（banner、HTTP Server/标题/登录页识别、TLS 证书）＋TTL OS 识别＋暴露面风险规则（Telnet/ADB/TR-069 等按严重度分级）＋已知漏洞签名匹配（精选快照）；报告落库并可导出 JSON 衔接 Kali/Metasploit 工作流；设备抽屉一键触发，或开启「陌生设备自动深度侦察」。
- **定时巡检**：默认每 5 分钟后台全网扫描，设备上下线、IP 变更、端口变化自动记入事件流；连续 2 轮未出现才判离线，避免瞬时抖动。
- **入侵检测**：新设备接入告警（白名单制）；被动嗅探 ARP/DHCP 广播——新设备入网即刻发现，不必等下一轮巡检；ARP 欺骗/网关劫持实时检测（网关 MAC 突变、IP-MAC 绑定冲突均触发严重告警，可弹系统通知）。
- **设备台账**：自定义命名、类型标记、备注、星标、已知设备白名单；每台设备近 24 小时在线时段时间线。
- **Web 控制台**：深色主题单页，仅绑定 127.0.0.1，不对外网暴露。

## 环境要求

- Windows 10/11（中文、英文系统均可）
- Python 3.9+（标准库为主，唯一第三方依赖 scapy）
- Npcap（scapy 发原始 ARP 包与被动嗅探依赖；若装过 Wireshark 通常已自带。未安装时自动降级为 ping 扫描模式，仅失去静默设备发现与实时嗅探能力）

## 安装

```
pip install scapy
```

Npcap 安装包：<https://npcap.com/>

## 使用

```
python lanscope.py serve              # 启动 Web 控制台（默认 http://127.0.0.1:8765，自动打开浏览器）
python lanscope.py serve --no-browser # 不自动打开浏览器
python lanscope.py scan               # 一次性扫描，终端输出结果表格
python lanscope.py scan --json        # JSON 输出，便于脚本调用
python lanscope.py recon <MAC|IP>     # 对单台设备深度侦察（全端口＋指纹＋风险）
```

serve 模式启动即做首轮全网扫描作为基线（不产生新设备告警），之后按设置的间隔自动巡检。首次扫描后建议在「设置」页把当前设备全部标记为已知，此后新出现的 MAC 才会触发新设备告警。

## 工作方式

- 扫描层：scapy（ARP 帧级发现）＋标准库 socket（端口 connect 扫描）
- 存储：SQLite（WAL 模式），数据文件在 `data/lanscope.db`
- 服务：标准库 http.server，仅监听 127.0.0.1
- 前端：原生 HTML/CSS/JS 单页，无构建步骤、无 CDN 依赖、离线可用

## 使用注意

- 端口扫描不覆盖 25/110/143：安全软件的「邮件防护」会在本机用 WFP 重定向明文邮件端口的连接，对任何目标 IP 都握手成功，产生假阳性（实测 iPhone 与路由器在这三个端口全部「开放」）。
- MAC 随机化（iOS/Android 的私有 Wi-Fi 地址）会让厂商识别失效，属正常现象；给这类设备自定义命名即可。
- IEEE OUI 库从国内访问约 30～40KB/s，全量约 6.6MB，首次更新需数分钟，在后台进行、不阻塞扫描；下载失败时使用内置精简库，下次启动自动重试。
- 系统弹窗通知使用 Windows 自带的 msg 命令，家庭版可能没有该命令，此时静默跳过，事件仍完整记录在控制台事件流里。
- 深度侦察只做识别与评估，不做漏洞利用——利用工作请在自己的靶场环境（如 Kali＋Metasploit）进行；报告里附带的 nmap 命令即为衔接入口。
- 深度侦察的全端口扫描：对回 RST 的设备约 10～40 秒；对静默丢包型设备（实测小米路由器）约 2 分钟——65535 个探测端口占满超时属正常。
